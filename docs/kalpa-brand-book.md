# Kalpa Brand Book

Version: Reconstructed working manual  
Date: August 7, 2026  
Status: Working brand system inferred from Kalpa’s public website, supplied logo asset, and HyperFrames design-system principles. This is a practical operational manual for product and deck-generation work, not a claim of being Kalpa’s original historical brand document.

## Document Purpose

This brand book exists for two reasons:

1. to give Kalpa a coherent visual and verbal system that can be reviewed and refined
2. to translate that system into rules the slideshow generator can actually use

The goal is not just to document a brand. The goal is to make Kalpa’s brand legible enough that software can generate work that feels recognizably Kalpa rather than generically corporate.

## Source Inputs

- Website: https://www.kalpainc.com/
- Logo asset: `Kalpa Inc Logo 1.png`
- Design-system reference: [HyperFrames](https://github.com/heygen-com/hyperframes), especially its `frame.md` / `DESIGN.md` approach to turning design language into reusable compositional rules

## Executive Summary

Kalpa should feel like a trusted ERP advisor with operational credibility, financial seriousness, and implementation realism. The brand should communicate confidence without arrogance, structure without stiffness, and expertise without consultant theater.

The most important translation for this product is:

- Kalpa is not a “template brand”
- Kalpa is a “system brand”

That means the visual language should be built from:

- architectural framing
- decisive hierarchy
- clean information structure
- calm surfaces
- one or two controlled moments of signal emphasis

It should not be built from:

- novelty effects
- generic SaaS cards
- overdecorated gradients
- stock enterprise clichés

## Logo Analysis

The supplied logo is the strongest visual anchor in the current brand system.

It communicates:

- angular structural precision
- interlocking forms
- vertical stability
- diagonal movement
- a system-building mentality
- a single warm highlight inside a cooler blue field

This means the broader design language should inherit:

- structural framing
- nested forms
- deliberate diagonals
- restrained accent punctuation
- a systems-oriented visual rhythm

## Logo Usage

### Preferred Treatments

- full-color logo on white or very light backgrounds
- full-color logo on clean navy fields with sufficient contrast
- single-color navy or white version where necessary

### Clear Space

Use the orange diamond from the mark as the minimum clear-space unit. Maintain at least one diamond-width of space around the full lockup.

### Minimum Size

- digital logo with wordmark: at least 120 px wide
- icon-only mark: at least 24 px

### Never

- distort the mark
- add gradients inside the mark
- rotate the mark
- outline the mark
- place it on noisy imagery without a clean container

### Supporting Brand Colors

- Signal Orange: `#FF8C00`
- Support Blue: `#7FBCDE`

### Neutrals

- Paper: `#F4F4F4`
- Surface White: `#FFFFFF`
- Warm Mist: `#EAE7DF`
- Border Mist: `#D9E2E8`
- Quiet Gray: `#6E7C87`
- Deep Charcoal: `#0F1A22`

### Color Roles

- `Kalpa Blue`: primary brand action, chart emphasis, section leads, key numbers
- `Kalpa Navy`: major authority fields, headers, executive structure, strong framing
- `Kalpa Orange`: signal accent, highlight marker, active state punctuation
- `Support Blue`: soft information field, supporting backgrounds, rail and divider logic
- `Paper` / `Surface White`: clean breathing room and neutral working surfaces

### Color Ratio Guidance

- 55-65% neutrals
- 20-30% blue / navy structure
- 8-12% support blue
- 3-6% orange signal emphasis

Orange should punctuate. It should not dominate.

### Accessibility Guidance

- body text on light backgrounds should use `#102132` or darker
- orange should not carry meaning by itself
- small text should avoid pale support blue
- navy fields require white or very light neutral text

## Typography System

The current source material suggests a clean, modern, business-first sans system. Since the available inputs do not establish an official proprietary type standard, the following is the recommended operational type system for product and slide work.

### Typeface Roles

- Display / Headline: `Sora` or `Inter Tight`
- Body / UI: `Inter`
- Mono / data accents: `IBM Plex Mono`

### Type Character

- bold but not loud
- compact
- precise
- readable
- controlled

### Type Scale Guidance

- Hero headline: 36-52 px
- Section headline: 24-32 px
- Slide headline: 22-30 px
- Supporting body: 12-16 px
- Caption / metadata: 10-12 px
- Large stat values: 24-34 px

### Usage Rules

- use weight and scale more than color for hierarchy
- all caps should be reserved for small labels, metadata, and navigation accents
- body copy should remain neutral and unobtrusive
- data numerals should feel compact and high-confidence

## Grid System

### Default Slide Grid

- 12-column conceptual structure
- generous outer margins
- one dominant anchor edge per slide
- one primary reading path
- two major content zones on most slides, not three or four

### UI Grid

- left column: intake, sources, workflow controls
- right column: active workspace and artifact review
- avoid pushing the central artifact below the fold

## Layout Principles

### Composition

- lead with structural balance
- maintain generous margins
- default to left alignment unless the slide type benefits from centered composition
- give every slide one obvious dominant message

### Spatial Rules

- large blocks should feel anchored inside a stable frame
- asymmetry is welcome if it feels structural rather than random
- negative space should be intentional, not accidental emptiness

### Surface Rules

- prefer borders and framing over theatrical shadows
- use high-trust neutral surfaces
- keep cards disciplined
- let the blue structure carry authority

## HyperFrames-Inspired Frame Principles

What is useful from HyperFrames is not its literal aesthetic. It is the system logic:

- design as a compositional rule set rather than a skin
- create reusable blocks and framed primitives
- use spacing and scale intentionally
- prefer border logic over heavy shadow
- treat themes as different composition strategies, not just alternate colors

Those ideas should be translated into Kalpa as:

- framed executive surfaces
- disciplined spacing
- modular stat bands
- poster-like hierarchy
- structural rails and edge anchors
- sparse but intentional geometric punctuation

## Slide Design System

This is the most important section for the slideshow generator.

### Design Goals

- every slide should feel boardroom-ready
- story clarity beats decoration
- layouts should feel designed, not template-stamped
- structure should be visible immediately
- every slide should feel like Kalpa, not anonymous enterprise software

### Core Slide Types

- Hero
- Challenge
- Proof
- Process
- Industry Grid
- Comparison
- Quote
- CTA

### Slide Art Direction Rules

- hero slides should combine strong hierarchy with a structural visual anchor
- challenge slides should feel diagnostic and organized
- proof slides should emphasize numbers, proof statements, and scannability
- process slides should feel directional and sequenced
- comparison slides should feel fair, clean, and decision-friendly
- quote slides should use restraint and high-contrast whitespace
- CTA slides should simplify rather than add complexity

### Approved Reusable Primitives

- angled side rail
- top-left or right-edge frame
- floating diamond signal marker
- modular stat cards
- process nodes on a directional beam
- framed comparison columns
- quote field with restrained accent
- folded-corner title tab
- industrial photo window with hard frame
- diagonal divider band

### Density Rules

- no body-copy walls
- one dominant headline per slide
- no more than one supporting paragraph in most layouts
- proof slides should rarely exceed three stats without restructuring
- process slides should rarely exceed four steps without redesign

### Typography On Slides

- the headline must remain legible in one glance
- support text must compress before overlapping
- calls to action should become simpler as they approach the end of the deck

## Diagram And Data Visualization Rules

- prefer bars, simple comparisons, and grids over ornate charts
- keep labels readable and obvious
- use blue as the default data color
- use orange only to emphasize
- never use rainbow palettes

## Generator Rules To Encode

When the tool generates themes, outlines, and slides, it should:

- prefer framed composition over generic cards
- use orange as signal rather than default fill
- preserve strong margin discipline
- enforce concise headlines
- avoid overcrowding text regions
- use realistic business and industrial imagery logic
- generate theme directions as compositional systems, not just color options
- keep any HyperFrames inspiration subordinate to Kalpa’s own identity

## UI Translation For The Product

The product UI should embody the same logic as the slides:

- a strong right-hand workspace
- fewer stacked sections
- less vertical sprawl
- calm surfaces with architectural accents
- theme selection as meaningful visual choice, not a hidden template toggle
- slide review that feels central, not appended below the editor

## Deck Review Checklist

Before a generated deck is considered acceptable, it should pass:

- Does the story feel executive and decision-oriented?
- Does each slide have one dominant message?
- Is orange used as a signal instead of a blanket fill?
- Do borders and structure feel intentional?
- Is imagery credible and relevant?
- Does the deck feel like Kalpa instead of generic enterprise software?
- Would the exported PPTX remain clean after handoff?

## Do / Don’t

### Do

- use blue and navy for trust and structure
- use orange with precision
- build hierarchy with space, type, and structure
- make layouts feel architectural and grounded
- support the spoken story with clear composition

### Don’t

- generate generic gradient-only corporate slides
- oversaturate with orange
- stack too much copy into narrow regions
- rely on decoration instead of hierarchy
- make every slide feel like a dashboard

- `frame.md` as a translation layer from brand to composition
